# UNICK — план доработки платформы

_Обновлено 4 октября 2026._

**Цель ближайшего этапа:** провести первый курс с реальными учениками. Для пилота по трекшн-карте это: 5 авторов, 5 курсов, 50 учеников.

**Критерий готовности:** автор без технического специалиста меньше чем за 60 минут собирает курс и отправляет ссылку. Ученики с телефона проходят уроки, сдают задания и получают обратную связь. Данные хранятся на сервере и защищены правами доступа.

---

## Этап 1. Ядро для пилота — ✅ сделано в этой итерации

**Архитектура**
- Слой данных отделён от интерфейса: `src/app/lib/backend/` (Supabase для боевого режима, localStorage для демо).
- Схема PostgreSQL с RLS (`supabase/migrations`). Права проверены 32 автотестами: чужой автор не видит и не меняет курсы, ученик без доступа не видит уроки, нельзя самому себе принять ДЗ, сменить роль или перепрыгнуть урок.
- Настоящая авторизация: регистрация, вход, подтверждение email, восстановление пароля. Демо-вход без пароля доступен только в демо-режиме.
- В CI перед деплоем запускаются проверка типов и тесты. Убраны неиспользуемые зависимости (MUI, emotion и др.).

**Автор**
- Конструктор курса: модули и уроки, сортировка, пять типов уроков (видео, текст, ДЗ, тест, материалы).
- Визуальный редактор текста (без HTML). Видео по ссылкам YouTube, VK Видео, Rutube, Kinescope или загрузкой файла. Прикреплённые материалы. Обложка загружается файлом.
- Тесты с одним или несколькими правильными ответами и порогом прохождения.
- ДЗ со сроком в днях от начала обучения.
- Доступ к курсу: по приглашению, свободная запись или «платный» (оплата — на этапе 2). Режим «уроки по порядку».
- Вкладка «Ученики и доступ»: ссылки-приглашения с лимитом мест, отключение ссылок, добавление ученика по email, закрытие доступа, прогресс каждого.
- Предпросмотр курса глазами ученика.
- Проверка ДЗ с файлами; принятое ДЗ засчитывает урок.

**Ученик**
- Вход в курс по ссылке-приглашению: регистрация → автоматическое вступление → курс.
- Страница программы курса с прогрессом и кнопкой «Продолжить».
- Урок: видео, текст, материалы, тест с разбором, сдача ДЗ с файлами, ответ автора. Закрытые уроки в последовательном курсе. Работает с телефона.
- Каталог: самозапись только на курсы со свободной записью.

**Исправлено**
- Пустой экран при обновлении любой страницы на GitHub Pages: `404.html` уходил в бесконечный редирект.
- Новый автор видел и мог редактировать демо-курсы чужой школы.
- Ученик открывал любой урок любого курса по прямой ссылке.
- XSS через HTML урока: теперь HTML очищается через DOMPurify.
- В чате на сообщения отвечал фейковый бот со случайными ответами.
- Выдуманные отзывы, «тысячи школ», «14 дней бесплатно» на лендинге и при регистрации. Лендинг переписан под то, что платформа умеет на самом деле.
- Нет политики ПДн и согласия: добавлены страницы `/legal/privacy` и `/legal/terms`, согласие при регистрации и в форме предзаписи.
- ID Google-таблицы с заявками удалён из публичного кода.
- Разделы-заглушки (платежи, потоки, команда, страницы, контент, «Вселенная») убраны из меню.

## Этап 3. Удобство и удержание — 2–3 недели после запуска

1. **Email-уведомления** (Supabase Edge Function + SMTP): автору — «пришло ДЗ», ученику — «ДЗ проверено», «открыт новый урок», напоминание неактивным через 3 дня.
2. **Аналитика автора на реальных данных:** воронка по урокам (где отваливаются), время до проверки ДЗ, активность за неделю. Сейчас страницы «Аналитика» и «CRM» считают по упрощённым формулам.
3. **Админка платформы** (`/admin`): авторы, курсы, ученики, метрики пилота для HADI. Сейчас это заглушка.
4. **Продуктовые события** (таблица `events`): время сборки курса, шаги, ошибки. Это нужно для гипотезы 3 о публикации курса за 60 минут.
5. **Realtime для чата и ДЗ** через Supabase Realtime. Сейчас данные обновляются при возврате на вкладку и раз в минуту.
6. **Сертификат** о прохождении (PDF с номером).
7. **Перевод оставшихся экранов** на новый слой данных: календарь, достижения, CRM. Проверить их на реальных данных.

## Этап 4. Продажи и сеть — модель «образовательная сеть + LMS»

1. **Оплата:** ЮKassa или Prodamus. Вебхук → Edge Function → запись с `source = 'payment'`. Нужны юрлицо, оферта и чеки по 54-ФЗ. Для комиссии 15% с сетевых продаж — сплит-платежи (ЮKassa для платформ).
2. **Публичные страницы:** автора (`/@slug`) и курса (`/c/slug`) с программой и кнопкой записи или оплаты.
3. **Каталог как сеть:** поиск, категории, рекомендации. Учёт источника записи (`network` / ссылка автора) для расчёта комиссии.
4. **Тарифы автора** — после проверки гипотезы 7 (фиксированная подписка против 990 ₽ + 15%).

## Технический долг

- Страницы автора («Ученики», «Аналитика», «CRM», «Календарь») и «Прогресс» ученика работают на новом слое, но формулы метрик упрощённые. Их нужно пересмотреть на этапе 3.
- Ответы на тесты проверяются в браузере: правильные варианты технически видны ученику. Для учебных тестов это допустимо. Для аттестации нужна серверная проверка через RPC.
- Нет e2e-тестов интерфейса. Добавить Playwright на три сценария: автор собирает курс, ученик вступает по ссылке, проверка ДЗ.
- В UI-ките (shadcn) часть компонентов написана под React 19. Overlay-компоненты исправлены, остальные стоит проверить при обновлении React.
